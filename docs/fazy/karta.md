| # | решение | адрес | канон |
|---|---|---|---|

🔴 **Решение 5 — то, ради чего фаза заведена.** `[У3]` Понятие получает адрес ввода ДО письма.
Инвентарь, составленный после текста, есть список того, что уже написано; составленный здесь — список
того, что придётся объяснить, и он ещё может изменить состав блоков. Обратный порядок означает, что
введение понятия превращается в переписывание готового текста, а это делают не всегда.

**Форма `PONYATIYA.md`** — по строке на понятие:

```
| понятие | роль | вводится в блоке | как |
|---|---|---|---|
| гранецентрированная кубическая упаковка | несущее | 1.2 | одной фразой через картинку слоёв |
| решётчатая упаковка | несущее | 1.2 | определением, начинается с определяемого |
| собственная функция преобразования Фурье | отсылка | 3.3 | содержания не даём, ссылка наружу |
| положительно определённый | общеизвестное | — | ставим прямо |
```

**Роль — закрытый список из четырёх, и он и есть решение** (К7): `несущее` — сюжет на нём висит,
объясняем полностью, сколько бы ни заняло · `мотивация` — работает мотивацией, объясняем ·
`отсылка` — содержания не даём и говорим это прямо · `общеизвестное` — знает работающий математик
не из этой области, ставим голым. **Пятого значения нет: понятие, не попавшее ни в одну роль,
вырезается из выпуска, а не остаётся необъяснённым.**

## ПРОЦЕДУРА

1. Написать `## Карта` — состав и порядок блоков по разделам. Схема раздела сверяется с типовыми
   (К9): схема, не встретившаяся в корпусе, — повод проверить раздел, а не гордиться оригинальностью.
2. Написать шапку каждого блока: четыре поля. Стиля в них нет, писать можно длиннее, чем в выпуске.
3. Заполнить `опирается` — по блокам, а не по разделам. Блок B опирается на A, если без A читатель
   не поймёт B.
4. Породить `PONYATIYA.md` из `## Понятия` разведки, назначить каждому понятию роль и блок ввода.
5. Предъявить владельцу: карта, шапки, инвентарь понятий. Ответ да / нет / правка.
6. Получив «да», вписать `ПРИНЯТО karta: <дата>` в `PONYATIYA.md`.

## ВЫХОД

`## Карта` · шапки всех блоков с непустыми четырьмя полями · `PONYATIYA.md` без слова `заполнить`,
со строкой приёмки. Текста под `====` ещё нет.

## ГЕЙТ ВЫХОДА — два условия: скрипт и верификатор

**Скрипт** — `python3 vypuski/check_bloki.py <файл>`: `[У3]`

1. состав блоков в карте совпадает с маркерами по тексту (избыточность нарочная — она и есть
   единственный способ поймать правку, сделанную в одном месте и забытую в другом);
2. у каждого блока непустые `зачем` · `мысль` · `объём`; статус из списка К9; в каждом разделе есть
   хотя бы один строгий блок;
3. 🔴 **граф опор непуст**: хотя бы один блок вне лида опирается на другой. Красное только на
   ПОЛНОСТЬЮ пустом графе — узкое условие выбрано намеренно, потому что «правильная» доля опор
   есть суждение, а пустой граф есть факт. `[У4]`
   ПОДЪЁМ: до У3 — требовать опору у каждого блока, кроме первого в разделе; мешает то, что замер
   такого требования на выпусках 2–3 не делался, и оно покраснело бы на принятых выпусках.
   [ДОЛГ: docs/DOLGI.md#Д16]
4. в `PONYATIYA.md` у каждого понятия названа роль из четырёх, и у ролей `несущее` и `мотивация`
   назван существующий блок; `grep -c "^ПРИНЯТО karta:"` = 1.

**Верификатор карты** — свежий субагент, промпт `docs/verifikatory/karta.md` дословно, на вход
только карта и шапки блоков, без текста и без разведки. `[У4]` Один вопрос: **достаточно ли шапки,
чтобы написать этот блок, не зная замысла.** Второе условие — зелёный вердикт.
