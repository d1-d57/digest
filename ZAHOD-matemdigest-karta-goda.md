### Схема строки

- `area` — лучшая догадка по разделу (алг. геометрия, теория чисел, топология, анализ, матфизика, комбинаторика, логика, вероятность, …); MSC если извлекается.

### Ворота отбора — кодируй как СКОР/ТЕГ, не как автоотсев
1. **широта / межпредметность — мастер-ворота** (`breadth_score` 0–5): ценнее всего материал, легибельный за границей своего раздела.
2. экспозиция-не-анонс (мост/объяснение vs сырой результат) — тег.
3. понятность широкому слою математиков — тег/скор.
4. значимость / вес события (`significance_score` 0–5).
5. добываемость (для книг/ресурсов) — тег.
Плюс: посчитать **долю Quanta**; расширенное определение «новости» = результаты + люди + премии + книги + события + юбилеи + интервью. **Предпочитай высокосигнальные источники**, чтобы сырая лента уже была качественной (меньше потом разгребать).

### Выходные артефакты
1. `materials.db` + `materials.csv` + `materials.json`.
2. `sources.yaml` — каждый реально использованный источник + рабочий способ доступа (ISSN/фид/URL) + **список FAILED** с причинами. (Это переиспользуемый реестр для будущего бота.)
3. Отчёт о распределении: `report.md` + `report.html` (простые графики, напр. через матплотлиб→PNG или инлайн-SVG): счёт **по категориям**, **по разделам**, **по месяцам**; **доля Quanta %**; **в неделю** (среднее/мин/макс) + гистограмма «тихие vs обвальные недели»; сколько с `breadth_score ≥ 3`.
4. `README.md` — как собрано и как обновить (перезапуск на новом окне двумя константами).

### КРИТЕРИЙ ГОТОВНОСТИ (может провалиться)
- `materials.db` существует и содержит **≥ 250 строк** за окно.
- **Все 5 категорий непусты**; покрыто **≥ 10 различных разделов**.
- В каждой строке НЕ `null`: `title`, `date`, `source_name`, `category`, `url`, `breadth_score`.
- Случайная выборка **15 url резолвится** (HTTP 200 / валидный DOI).
- `report.html` рендерится и показывает разбивки по категории/разделу/месяцу + долю Quanta.
- `sources.yaml` честно перечисляет рабочие И **FAILED** источники (каждый FAILED реально ошибается на переспросе).

## 4. ВЕРИФИКАТОР (свежий субагент, ДРУГОЙ метод)
Отдельный субагент, не автор сбора: проверить программно — (a) числа в отчёте == счёт строк в БД (**запросом к БД напрямую**, не по числам самого отчёта); (b) выборка из 15 ссылок резолвится; (c) каждый источник из FAILED реально возвращает ошибку на независимом переспросе. **Список расхождений должен быть ПУСТ.**
