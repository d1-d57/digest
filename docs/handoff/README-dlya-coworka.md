# Как продолжить в Cowork

Этот архив — **контекстный слой** проекта MATEMDIGEST (стратегия, решения, заходы), собранный из стратегического чата. Сам репозиторий с кодом и базой у тебя уже локально: `~/Documents/GitHub/matemdigest-map/`.

## Шаги
1. Открой в Cowork папку репозитория `~/Documents/GitHub/matemdigest-map/`.
2. Положи содержимое этого архива внутрь репо (предложение: `docs/handoff/` — туда `HANDOFF.md` и папку `zahody/`). `pull_surveys.py` уже есть в репо — копию из архива можно не класть.
3. Первым делом скажи агенту: **«Прочитай `docs/handoff/HANDOFF.md` целиком, затем действуй по разделу „Незакрытое — следующие шаги“».**
4. Запусти шаг 1 — редакторскую отбраковку: файл `zahody/ZAHOD-1b-redaktorskaya-otbrakovka.md`.

## Что изменилось с переходом в Cowork
Раньше была петля «аналитик в чате пишет заход → Claude Code исполняет → отчёт через zip». В Cowork агент **читает и правит репо напрямую** — отчёт через архивы больше не нужен, и промахи (как заход-1, сделавший гигиену вместо отбраковки) ловятся сразу в файлах.

Заходы остаются валидными техзаданиями. Можно:
- **вести обе роли в Cowork** (агент сам и планирует, и исполняет на репо), или
- **держать Claude Code исполнителем** и запускать заходы как раньше, но уже без пересылки — файлы общие.

## Дисциплина (из захода, не терять)
- Число годных при отбраковке — это **ОТВЕТ, а не цель**. Не тянуть к 300, не резать к 150.
- **Сырьё не удалять** — курирование обратимым флагом (`keep`/`fitness`), не `DELETE`.
- Гигиена данных ≠ редакторская отбраковка: судим **КОНТЕНТ** (годится ли в рассылку), не чистоту таблицы.

Полный контекст, эмпирика, архитектура и gotchas — в `HANDOFF.md`.
