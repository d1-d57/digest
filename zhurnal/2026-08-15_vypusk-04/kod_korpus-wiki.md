## 4. 🔴 КОММИТ СВОЕЙ ЗОНЫ — ПОСЛЕДНИЙ ХОД ЗАХОДА, НЕ ОПЦИЯ
Ты работаешь host-side и в `.git` ПИШЕШЬ — значит коммитишь САМ, никому не передавая:
```
git --no-optional-locks add -- vypuski/tablica_sochetaemosti.json.gz vypuski/reestr_korpusa.tsv vypuski/sobrat_korpus.py zhurnal/2026-08-15_vypusk-04/korpus-wiki-vyvod.txt zhurnal/2026-08-15_vypusk-04/kod_korpus-wiki.md                     # вводит НОВЫЕ пути в индекс

git --no-optional-locks show --stat                        # обязаны быть ТОЛЬКО твои пути
```
🔴 **ОБА хода обязательны, ни один не лишний** (полное «почему» и цена — `../docs/kak-delat/GIT-disciplina.md §3`):
- **`add`** — pathspec-коммит знает только **отслеживаемые** пути; новый файл без `add` даёт `did not match any file(s) known to git`.
- **`-- <пути>` в самом `commit`** — иначе `commit` забирает индекс ЦЕЛИКОМ, вместе с чужим, застейдженным кем угодно рядом с тобой (репо `materials/` общий, писателей трое). *Обе половины оплачены 21.07 в один вечер: голый `commit` подмёл чужой индекс — коммит на 89 файлов вместо трёх; «починка», убравшая `add`, завалила все 10 коммитов повторно.*
⚠ **Хук `pre-commit` покраснел — сначала посмотри, на ЧЬИХ путях.**
- Красное на ТВОИХ путях (новый `.md` не зарегистрирован в `../../docs/KARTA.md §6`, битая ссылка) — **чини, не обходи**: там только твоё, обходить нечего.
- Красное на ЧУЖОМ, унаследованном долге (ворота дают сотни ❌ старых нарушений) — законный обход, но ТОЛЬКО с причиной; голый `--no-verify` инструмент отклонит, а причина сама уедет в `INCIDENTY.md`:
```
python3 $MAT/_generator/tools/git_zona.py commit --zone <зона> \
    --no-verify "чужой долг: <что именно покраснело>" -m "<что и зачем>" --push
```
Ту же причину назови отдельной строкой отчёта долгом. *Урок 9: обход был законен по канону и не существовал в инструменте — первый же коммит владельца встал на чужом долге.*
**Коммит не прошёл по ВНЕШНЕЙ причине** (чужой лок, конфликт, detached HEAD) — чужое состояние репозитория НЕ чини: зафиксируй файлы и напиши в отчёт отдельной строкой «коммита нет, причина такая-то, нужно ваше действие». Это законный отчёт. Молчаливое «сделано» при незакоммиченной зоне — брак: приёмка гоняет тот же гейт первым ходом и завернёт отчёт, не читая (`RUKOVODSTVO §Приёмка`, гейт 0).

**Зачем это вообще.** Мы платим сутками выкачки за 45+ МБ текста, а используем один срез — пары
«объект + глагол». Владелец: *«надо придумать не один инструмент, а с десяток, которые суммарно
покроют все вопросы про лексику и сочетаемость»*. Все срезы ниже делают ОДИН разбор корпуса и
пишутся рядом с таблицей. Порядок — по убыванию пользы, и он не случайный: **если времени хватит
не на всё, делай сверху вниз и скажи, где остановился.**

### 🔴 РАМКА, БЕЗ КОТОРОЙ СРЕЗЫ БЕСПОЛЕЗНЫ

Цель не «сделать текст википедийным». Цель — **убрать обороты, выдающие человека, который не
говорит на математическом русском**. Отсюда размен, названный владельцем прямо: лёгкая казённость
меньшее зло, чем чужой оборот. И отсюда форма продукта: **не список подозрений, а КАРТА ЗАМЕН** —
пометить мало, надо предложить чем заменить. Приоритет источников для замены: наши принятые
тексты → книги → вики. Полностью — `docs/slovar-korpusa.md`, раздел «РАМКА ЗАДАЧИ».

### 6.1 · ПОРТРЕТ ОБЪЕКТА (word sketch) — главный срез, делать первым

Для каждого математического объекта — сводка его сочетаемости по грамматическим отношениям, а не
по окну. Приём известный: это **word sketch** Килгарриффа, тот же, что в Sketch Engine.

**Мера типичности — `logDice`, НЕ голый PMI и не MI3.** Формула:
`logDice = 14 + log2( 2·f(объект,глагол) / (f(объект) + f(глагол)) )`. Причина выбора названа
авторами меры: logDice не зависит от размера корпуса, поэтому числа остаются сравнимыми, когда
корпус подрастёт со следующей выкачкой; PMI и MI3 задирают редкие пары, а у нас весь материал
редкий. Порог осмысленности начинается около 7 — считай его, а не подгоняй.

**Отношения, которые вынимаются раздельно** (в этом вся разница с нынешним окном):

| отношение | пример | зачем нам |
|---|---|---|
| объект — ПОДЛЕЖАЩЕЕ при глаголе | граница ПРОХОДИТ | ядро задачи: «граница ушла» ловится здесь |
| объект — ПРЯМОЕ ДОПОЛНЕНИЕ | СДВИНУЛИ границу | второй по частоте класс ошибок |
| объект + ПРЕДЛОГ + падеж | оценка СВЕРХУ, граница ДЛЯ | управление, отдельный источник кальки |
| прилагательное при объекте | верхняя граница, точная оценка | штампы вида «впечатляющий результат» |

🔴 **Здесь нужен синтаксический разбор, а окно 4 токена его не заменяет.** Нынешний быстрый режим
даёт шум: «речь ИДЁТ о ГРАНИЦЕ» превращается в пару «граница + идти», и в таблице «граница идти»
стоит 8 раз — то есть корпус подтверждает оборот, который владелец забраковал.
**Как уложиться по времени:** парсер (`spacy.load('ru_core_news_sm')` БЕЗ `disable=['parser']`)
гоняется не по всему корпусу, а только по предложениям, где встретился объект из топ-300 по
частоте. Это отсекает ~90 % текста. Пары окна оставь как есть, вторым, более грубым слоем — они
уже посчитаны и на них стоят прежние числа.

**Выход:** `vypuski/portret_objektov.json.gz` — по объекту четыре отношения, у каждого список
`{глагол/предлог, частота, logDice, слои-источники}`. Число объектов в нём назови командой
`python3 -c "import gzip,json;print(len(json.load(gzip.open('vypuski/portret_objektov.json.gz','rt',encoding='utf-8'))))"`.

### 6.2 · КАРТА ЗАМЕН — то, ради чего всё затевалось

Для оборота, не подтверждённого корпусом, предложить, чем заменить. Механика без нейросети:
берём объект, берём его портрет, отдаём верхние по `logDice` глаголы того же залога и вида —
это и есть кандидаты. Судья (`docs/verifikatory/idioma.md`) выбирает из них, а не выдумывает.

**Выход:** `vypuski/karta_zamen.jsonl` — строка на оборот: `{объект, глагол_подозрительный,
kandidaty: [{глагол, logDice, sloj}], est_v_etalone: true|false}`. Поле `est_v_etalone` показывает,
нашлась ли замена в НАШИХ текстах: если да, она идёт первой независимо от logDice.

### 6.3 · РЕЕСТР ИМЁН С ВАРИАНТАМИ НАПИСАНИЯ

Ценность не в списке фамилий, а в **вариантах**: Дельсарт или Дельзарт, Вязовская или Виазовска.
Википедия отдаёт их даром — через перенаправления: `action=query&prop=redirects&titles=<статья>`.
Собери по статьям-персоналиям: каноническое написание плюс все редиректы.

**Выход:** `vypuski/imena.tsv` — `каноническое · варианты через ; · частота в корпусе`.

### 6.4 · ТЕРМИНЫ ПРОЕКТА — через сравнение с общим русским

Приём стандартный: **log-likelihood против референсного корпуса**. Слово, частое у нас и редкое в
общем русском, — термин. Референс бери из пакета `wordfreq` (`pip install wordfreq`, проверено —
качается): `wordfreq.word_frequency(слово, 'ru')`. Порог по log-likelihood считай, а не назначай.

⚠ **Владелец сомневается в ценности этого среза, и сомнение обоснованное:** термин обычно проще
загуглить, чем искать в списке. Единственное применение, где список выигрывает у поиска, — проверка
в обратную сторону: термин, который МЫ употребили, существует ли он в русской математике или
переведён на ходу. Делай ради этого, не ради словаря.

**Выход:** `vypuski/terminy.tsv` — `термин · частота у нас · частота в общем русском · log-likelihood`.

### 6.5 · ПАЛИТРА СВЯЗОК И ПРОФИЛЬ СТИЛЯ — по слоям раздельно

Частоты дискурсивных маркеров и структурных признаков, посчитанные ОТДЕЛЬНО по каждому слою:
книги · вики · наши тексты. Раздельно — потому что замер 17.08 показал, что слои разные: «является»
229 на миллион в вики против 55 у нас, «следовательно» 197 в книгах против нуля у нас.
Признаки: длина предложения, доля страдательных причастий, доля отглагольных существительных
(`-ание/-ение/-ация`), частота вводных, длина цепочек родительного падежа.

🔴 **Профиль-ориентир строится по КНИЖНОМУ слою и нашим текстам, вики в него не входит** — иначе
инструмент будет тянуть в канцелярит, и это показано числом, а не вкусом.

**Выход:** `vypuski/profil_stilya.json` — по слою словарь признаков; плюс строка, насколько наш
выпуск 4 отклоняется от книжного профиля по каждому признаку.

### 6.6 · 🔴 УСТОЙЧИВЫЕ МНОГОСЛОВНЫЕ ОБОРОТЫ — ПРОБЕЛ, КОТОРЫЙ ЗАКРЫВАЕТСЯ ЗДЕСЬ

**Пары «объект + глагол» ловят меньшую половину задачи, и это посчитано на нашем же стенде.**
Команда, воспроизводящая счёт (из корня репо):

```
python3 -c "
import json
r=[json.loads(l) for l in open('vypuski/pary_idiom.jsonl',encoding='utf-8')]
r=[x for x in r if 'id' in x and x['klass']!='snyato-vladelcem']
m=[x for x in r if len(x['oborot'].split())>=3]
print(f'оборотов {len(r)}, многословных {len(m)}')"
```

На 2026-08-17 печатает: **оборотов 21, многословных 13.** То есть «упирается в потолок», «задача
ничего не отдала наружу», «оценки пошли навстречу друг другу», «делает утверждение о том, что» —
почти две трети забракованного владельцем — нынешним разбором НЕ ловятся ни в каком виде: там нет
пары «одно существительное + один глагол», там речевая формула целиком.

**Приём — lexical bundles: повторяющиеся n-граммы.** Длину бери от двух слов до шести: короче —
это уже пары, которые считает нынешний разбор, длиннее — почти не повторяется. Считай по леммам и
по словоформам раздельно: формула часто застывает в конкретной форме («с точностью до», «без
ограничения общности», «тогда и только тогда»). Порог частоты подбери замером, а не назначь:
прогони на нашем же материале и назови, при каком пороге список перестаёт тонуть в случайных
сочетаниях — команду и число в отчёт. Ориентир из практики корпусной лингвистики — порядка пяти
вхождений на слой, но это ориентир, а не значение.

🔴 **Читаются они по тому же несимметричному правилу, что и пары, и слои здесь работают сильнее
всего:** оборот, встречающийся в книгах или наших текстах, — принят; оборот, живущий ТОЛЬКО в
нейросетевом слое, — прямой кандидат в брак. Именно на многословных формулах нейросетевой почерк
виден лучше всего: одиночный глагол может совпасть случайно, пятисловная формула — почти нет.

**Выход:** `vypuski/oboroty_ngram.json.gz` — n-грамма: `{частота по слоям, длина, есть_в_etalone}`.
Плюс отдельный файл `vypuski/oboroty_tolko_nejro.tsv` — те, что есть только в нейросетевом слое,
отсортированные по частоте. Второй файл — рабочий список для владельца: он читает его глазами и
выносит вердикты, а вердикты идут в стенд `pary_idiom.jsonl`.

**Проверка, что срез работает:** прогони его по выпуску 4 и посмотри, попали ли в список
многословные обороты, которые владелец уже забраковал (они выписаны в `docs/slovar-korpusa.md`,
раздел «Обороты, признанные незаконными»: «упирается в потолок», «другая стенка», «задача ничего
не отдала наружу»). Назови числом, сколько из тринадцати известных многословных находок срез
поймал. Это прямой замер полноты, и он может провалиться — тогда так и скажи.

### 6.7 · УПРАВЛЕНИЕ: ТЕРМИН + ПРЕДЛОГ + ПАДЕЖ — отдельным файлом, не внутри портрета

В портрете объектов предлоги идут одним из четырёх отношений, но владелец назвал этот срез
отдельно, и правильно: калька приходит именно через управление. «Оценка НА» вместо «оценка
СВЕРХУ», «доказательство ДЛЯ» вместо «доказательство ЧЕГО», «граница В» вместо «граница ДЛЯ».
Собери отдельно, потому что пользоваться этим будут отдельно.

**Как:** по синтаксическому разбору — тройка `(лемма термина, предлог, падеж зависимого)`, частота
по слоям, logDice. Падеж брать из морфологии spaCy (`token.morph.get('Case')`), а не угадывать по
предлогу: у «в» и «на» падежей два, и они означают разное.

**Выход:** `vypuski/upravlenie.tsv` — `термин · предлог · падеж · частота · слои`.

### 6.8 · ПАЛИТРА СВЯЗОК — отдельным файлом, по слоям

То же, что в срезе профиля стиля, но вынесенное отдельным списком: чем реальные тексты соединяют
утверждения. «Отсюда», «значит», «положим», «тем самым», «в самом деле». Нужен не для того, чтобы
считать частоты, а чтобы было ИЗ ЧЕГО выбирать замену, когда связка в тексте звучит чужеродно.

🔴 **С поправкой, доказанной замером 17.08:** частоты по слоям сильно расходятся — «следовательно»
в книгах 197 на миллион знаков, в наших принятых выпусках ноль. Поэтому палитра сдаётся как список
возможностей С УКАЗАНИЕМ СЛОЯ, а не как норма частоты. Наш слой в ней главный: если связка есть у
нас — она первая в списке.

**Выход:** `vypuski/svyazki.tsv` — `связка · частота на миллион знаков по каждому слою`.

2026-08-16, поводом стал заход, который сделал работу и не закоммитил НИЧЕГО: *«он ничего не

**ПОРЯДОК ЖЁСТКИЙ, ОН НАЗВАН ВЛАДЕЛЬЦЕМ: сначала все коммиты → потом все ветки → потом вывоз.**
Обратный порядок не работает технически: влитие отказывает на грязном дереве, вывоз — на невлитом.

**1 · ВСЕ КОММИТЫ.** Ничего не осталось вне git — ни в рабочем репозитории, ни в соседних, до
которых ты дотянулся по ходу работы:
```
for R in <репозитории, которых ты касался>; do
  echo "== $R"; git -C $R --no-optional-locks status --porcelain
done
```
Своя зона — своими путями (`add` + `commit -- <пути>`). Чужая содержательная работа — НЕ твоя:
называешь строкой в отчёте и оставляешь. Пусто у всех — так и напиши числом «вне git 0».

**2 · ВСЕ ВЕТКИ.** Невлитого не осталось: `git --no-optional-locks branch --no-merged <основная>`.
Каждая оставшаяся ветка названа поимённо с причиной, почему она жива. 🔴 Ветку-витрину (`main` там,
где с неё публикуется сайт) НЕ вливать — влитие туда есть публикация и решение владельца.

**3 · ВЫВОЗ.** `git --no-optional-locks log --oneline @{u}.. | wc -l` → 0 по каждому репозиторию.
Ненулевое означает, что работа существует только на этом диске.

**4 · ПРОВЕРКА ФАКТОМ, А НЕ ПАМЯТЬЮ.** Три числа по каждому репозиторию — вне git · невлитых ·
невывезенных — печатаются командой и уходят в `## ОТЧЁТ` дословно. Ненулевое число, оставленное без
объяснения, приёмка читает как несделанную работу: она гоняет те же команды первым ходом.

🔴 **Отчёт без этих чисел не принимается.** «Я закоммитил» — не то же самое, что `status --porcelain`
пустой: за одну сессию работа не доезжала трижды, каждый раз с честным «сделано» в отчёте.
