# MATEMDIGEST · карта года

Карта жизнеспособности для еженедельной Telegram-рассылки материалов высокого уровня
по математике («Quanta для математиков»). Это **база кандидатов за скользящее окно 12 месяцев**,
скоренная и тегированная, + отчёт о распределении + реестр источников.

> **Это НЕ бот и НЕ рассылка.** Только карта: `materials.db` + отчёт + `sources.yaml`.
> Сборка рассыльщика — отдельный этап (реестр источников здесь и есть его фундамент).

## Что получилось (окно 2025-07-01 → 2026-07-10)

| | |
|---|---|

| Категории A–E | все непусты (A 301 · B 43 · C 86 · D 278 · E 72) |

| Доля Quanta | **10.0 %** (потолок ~25 % соблюдён) |
| breadth_score ≥ 3 | **574** (≥ 4 — «высшая широта» — весомый пул для куратора) |

Артефакты: `materials.db` (SQLite), `materials.csv`, `materials.json`,
`sources.yaml` (рабочие + FAILED + пробелы охвата), `report.md`, `report.html`.

## Как обновить (перезапуск на новом окне — ДВЕ константы)

```bash
pip install --user requests feedparser beautifulsoup4 pyyaml matplotlib lxml
# 1) правишь окно в config.py:
#    FROM  = "2025-07-01"
#    UNTIL = "2026-07-10"
python3 build.py       # тянет всё заново (Crossref + WP REST + RSS + JSON субагентов) -> materials.*
python3 report.py      # -> report.md + report.html
python3 verify.py      # автономная проверка гейта (числа из БД, резолв ссылок, FAILED)
```
`build.py --cached` пересобирает из `data/raw_cache.json` без похода в сеть (быстрая итерация скоринга/отчёта).

Категории B и E (Bourbaki/ICM/JMM, премии, книги/юбилеи/интервью) собираются веб-разведкой
и лежат как `data/*.json` — при обновлении окна их надо пере-собрать (в проекте это делали
3 параллельных субагента; см. ниже «Как собрано»).

## Как собрано (механизм по категориям)

- **A · проф. журналы** — Crossref REST по ISSN (`/journals/{ISSN}/works`, polite pool с `mailto`).
  Логика из `pull_surveys.py`. Bull AMS / УМН / EMS / Expo Math берём целиком; Notices —
  фильтр по длине; Bulletin LMS — только «Survey Article».
- **C · научпоп** — Quanta через `www.quantamagazine.org/wp-json/wp/v2/posts` (годовой охват
  174 поста, math-фильтр по классификатору + смежное); plus.maths и AMS Feature Column — RSS.
- **D · блоги** — годовой охват через WordPress REST: `.wordpress.com`-блоги →
  `public-api.wordpress.com`, self-hosted → `wp-json`/RSS. **Ключевой урок:** RSS отдаёт лишь
  5–25 последних записей — на год не хватает; REST-API решает это.
- **B · обзорные площадки** — скрейп bourbaki.fr (сезоны), ICM 2026, JMM Current Events Bulletin,
  Takagi Lectures (веб-разведка субагентом → `data/b_venues.json`).
- **E · разовое/люди/события** — премии (`data/e_prizes.json`), книги/юбилеи/интервью
  (`data/e_people.json`), YouTube (RSS по channel_id).

Пайплайн: `fetch_*` → нормализация → дедуп (url+title) → фильтр окна → junk-дроп →
классификация раздела → скоринг → `materials.db` + экспорт.

## Рубрика скоринга (прозрачная эвристика — карта, не приговор)

Отбор в рассылку субъективен, поэтому мы **скорим и тегируем, но не выкидываем** (кроме явного
не-мат мусора). Скоринг — детерминированная эвристика (`score.py`), не LLM-построчно: воспроизводимо,
дёшево на 780 строк, и куратор до-оценивает верхний слой вручную.

- **`breadth_score` 0–5 (мастер-ворота)** — легибельность за границей своего раздела. База по
  (категория, тип, источник): попсай / Bourbaki / ICM / премии / интервью — высокая; узкий тех-обзор —
  средняя; тех-пост блога — низкая. Бонусы: ключи «why/how/explain/solved/breakthrough» (+1),
  упоминание ≥2 разделов (+1, тег `cross-field`).
- **`significance_score` 0–5** — авторитет источника + вес события (Fields/Abel/ICM-пленар = 5,
  Bourbaki/Notices-feature = 4, блог = 2–3); ключи «resolves/proves/settles/conjecture» (+1).
- **`area`** — классификатор по ключевым словам title+summary (+ subject из Crossref); MSC где извлекается.
- **теги** — `expository`/`announcement`, `legible`, `cross-field`, `extractable`, `is_quanta`, `type:*`.

## Проверка (гейт §3 + верификатор §4)

`verify.py` — независимая проверка ДРУГИМ методом: числа отчёта сверяются **прямым запросом к БД**
(а не по тексту отчёта), случайные 15 URL резолвятся, каждый FAILED-источник переспрашивается и
обязан снова ошибиться. Список расхождений должен быть пуст.

## Консолидация: охват и пробелы

**Богатые категории.** A (журналы, 301) и D (блоги, 278) — детерминированный годовой охват через
Crossref и WordPress REST, надёжно и воспроизводимо. C-Quanta (86 с math-фильтром) и B (Bourbaki+ICM+JMM+Takagi,
43 в окне) — плотные и высокосигнальные. Разделы распределены широко: теория чисел (156), матфизика (90),
комбинаторика (37), CS (30), топология, алгебра, алг. геометрия…

**Тонкие места (честно).**
- **Юбилеи** — самый слабый блок (автоматизация плоха): надёжны Серр-100 и Вальдшмидт-80, массового
  списка круглых дат с URL нет.
- **RSS-усечение** — Woit, Aaronson, plus.maths и все YouTube-каналы отдают ~10–25 последних записей;
  для частых каналов (Numberphile/Veritasium) охват частичный (помечено `OK_PARTIAL`).
- **ICM 2026 приглашённые** (~180 имён) — страница IMU это JS-SPA, взяты только 16 пленарных.
- **Премии на ICM** (Fields/Chern/Gauss 2026) — объявляются 23.07.2026, после конца окна → лауреаты `null`.
- **Даты-«только год»** (~22 записи, в осн. премии/книги) — сгруппированы в отчёте отдельным бакетом `2026`.

**Топ-3 следующих улучшения.**
1. **Юбилеи** — подключить курируемый CSV «крупные математики + даты рождения/смерти», сверять с окном
   программно (сейчас это ручной пробел).
2. **Годовой охват RSS-only** — для Woit/Aaronson/plus.maths добрать архивы через сайтмап/пагинацию
   (убрать `OK_PARTIAL`); для YouTube — перейти с RSS на пагинируемый источник (playlist-«uploads»).
3. **Скоринг верхнего слоя** — прогнать LLM-оценку широты/значимости по кандидатам с `breadth_score ≥ 3`
   (≈574 строки), чтобы отранжировать пул для куратора точнее эвристики.
