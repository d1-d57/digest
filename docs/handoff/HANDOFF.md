## Текущее состояние (одним абзацем)
Строим **еженедельную Telegram-рассылку «Quanta для математиков»** — курированные осмысления (мосты-объяснения) по всей математике для широкого слоя математиков. Вопрос «хватит ли материала на ~5–8 разнообразных в неделю» **закрыт положительно**: собрана карта года — 738 кандидатов за 2025-07-01…2026-07-10 по 5 категориям источников (база + отчёт + реестр источников + верификатор, всё в репозитории). **Сейчас на очереди три вещи:** (1) редакторская отбраковка базы до реально-годного слоя — честная оценка аналитика ~270–315 годных (~5–6/нед), но durable per-row вердикт ещё НЕ проставлен, потому что предыдущий заход по ошибке сделал только гигиену данных; (2) добор пропущенных источников; (3) затем — сам слой отбора/осмысления и прототип рассылки, где вся ценность.

## Что это за продукт (концепция — не потерять)
- Еженедельно, **5–8 материалов/выпуск**, каждый = одно осмысление (мост-объяснение) + ссылка. Нативно в телеграм, сайт для MVP не нужен.
- **Аудитория:** широкий слой математиков (≈ со 2–3 курса до профессионалов).
- **Ценность:** материал существует, но не приходит к владельцу («живу в телеграме, на сайты не хожу»). Полная автоматизация; роль владельца — опциональная редакторская проверка «понятно / не врёт» (это forcing-function для него самого).
- **НЕ сырые новости о статьях, а осмысления.** Единица ценности — **МОСТ**: экспозиция, делающая результат легибельным за границей своего раздела. Мост-строитель ≠ автор статьи (даём Quanta / Kalai / Bourbaki-экспозе, а не arXiv-препринт или технический пост автора).
- Платный тир «глубже + архив» — позже.

## Ключевые проектные решения (с обоснованием)

| Решение | Суть | Почему |
|---|---|---|
| **5 категорий источников** | A проф. журналы · B большие обзорные площадки · C научпоп высокого класса · D блоги математиков · E разовое/люди/события | Покрыть весь спектр «что происходит», а не только Quanta |
| **Ворота значимости (скор, не бинарно)** | ① широта/межпредметность (**мастер-ворота**) ② экспозиция-не-анонс ③ понятность широкому слою ④ значимость события ⑤ добываемость | Отбор субъективен → скорим и тегируем, человек курирует верх |
| **Потолок Quanta ~25%** | Quanta ≤ ~четверти выпуска | Иначе рассылка теряет причину существовать (это не «пересказ Quanta») |
| **Буфер / очередь** | Придержать обвальные недели, отдавать ровно | Сглаживает месячные (Notices) и квартальные (Bourbaki, премии) всплески в ровный недельный поток |
| **Расширенное определение «новости»** | результаты + люди + премии + книги + события + юбилеи + интервью | «Учёному 80» или «вышла биография» — законная новость для этой аудитории |
| **Bridge principle** | Единица = мост, а не пункт | См. выше; поэтому одно событие ≠ N строк (ICM «докладчик X» схлопывается в «состав пленарных») |

## Техническая архитектура (важные уроки)

- **A журналы** — Crossref REST по ISSN (`api.crossref.org/journals/{ISSN}/works`), логика в `pull_surveys.py`. Bull AMS/УМН/EMS/Expo берём целиком, Notices — по длине, Bulletin LMS — только «Survey Article».
- **C/D научпоп и блоги — ГЛАВНЫЙ УРОК: RSS отдаёт лишь 5–25 последних записей → для годового backfill бесполезен.** Годовой охват — через **WordPress REST** (`public-api.wordpress.com/rest/v1.1/sites/{site}/posts` для `.com`-блогов; `wp-json` для Quanta/self-hosted). RSS — только для опроса вперёд.
- **B площадки** — скрейп: `bourbaki.fr` (сезоны), ICM 2026, JMM Current Events Bulletin, Takagi (веб-разведка субагентом → `data/b_venues.json`).
- **E** — премии/книги/юбилеи/интервью (субагенты → `data/e_prizes.json`, `data/e_people.json`), YouTube RSS по `channel_id`.
- **Фиды гниют** (всё зафиксировано в `sources.yaml`): n-Cat Café `atom.xml`→404 (рабочий `atom10.xml`); AMS Feature Column→`blogs.ams.org`; `api.quantamagazine.org` блокируется Cloudflare (рабочий фронт `www.quantamagazine.org/wp-json`).
- **Пайплайн:** `fetch_*` → нормализация → дедуп (url+title) → фильтр окна → junk-дроп → классификация раздела → скоринг (`score.py`, детерминированная эвристика, не LLM-построчно) → `materials.db` + экспорт. Отчёт `report.py`, проверка `verify.py` (читает БД напрямую, `exit 0`).

## Gotchas (на чём легко споткнуться)
- **«Чистка» ≠ редакторская отбраковка.** Прошлый исполнитель принял первое за второе. Формулировать задачу как суждение о **КОНТЕНТЕ** (годится ли в рассылку), не о качестве данных. «БД чиста по гигиене» — это НЕ ответ.
- **Экспозиция ≠ пригодность.** Спец-обзор (Expositiones, УМН) может быть экспозицией, но нечитаем вне подполя → OUT для широкой рассылки.
- **«Дубли по URL» — законные разные материалы.** ICM/Bourbaki/Takagi на общих посадочных страницах: 51 такой случай. Схлопывание = удаление сырья и занижение числа. Не трогать (кроме перетегирования одного события в один пункт при СБОРКЕ выпуска, не в базе).
- **Даты «только год»** (~22 записи, в осн. премии/книги) — отдельный бакет в отчёте, не терять.
