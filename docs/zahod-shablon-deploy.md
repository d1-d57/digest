# Шаблон захода: публикация выпуска

Копировать в корень как `ZAHOD-<номер>-deploy-<NN>.md`, заменить `<NN>` на номер выпуска и `<ДАТА>` на папку выпуска, отправить в Claude Code словами «прочитай файл и выполни». Переписывать заново не нужно — заход отработан на выпусках 1–3, меняются только номер и заголовок.

**Первый выпуск уже опубликован**, поэтому шаги «создать репозиторий» и «включить Pages» из шаблона убраны: они делаются один раз. Если репозитория почему-то нет — взять их из `ZAHOD-8-deploy-site.md` (структура репозитория с тех пор сменилась на Hugo, см. ниже — сам план создания репозитория и включения Pages актуален, содержимое `site/` из него уже нет).

```markdown
# Канал исполнителя — MATEMDIGEST · ЗАХОД-<номер>: опубликовать выпуск <NN>

**Кому:** Claude Code, чистый контекст. Читать только этот файл и то, что здесь названо. В проект не погружаться — заход самоценный.
**Рабочая папка:** корень репозитория `matemdigest-map` (там, где лежит этот файл).
**Оценка:** 5–10 минут, задача техническая.

## 0. ПЕРВЫЙ ХОД

Прочитать файл целиком, записать план в `## ПЛАН` внизу, начать. Блокеры — в `## ВОПРОСЫ`, продолжать с тем, что можно без ответа.

## 1. ЧТО ЕСТЬ

Репозиторий `matemdigest-map` — рабочий и приватный: база `materials.db`, заходы, черновики, документация. Наружу не идёт.

Публикуется только папка `site/` — это **отдельный git-репозиторий** со своим удалённым адресом `github.com/d1-d57/digest`. С 2 августа 2026 сайт собран на **Hugo**: GitHub Actions (`site/.github/workflows/hugo.yml`) собирает и деплоит на каждый пуш в `main`, источник Pages в настройках репозитория — **workflow, не ветка**. Титульная страница больше не файл, а шаблон + данные:

```
site/
  data/vypuski.yaml          ← ЕДИНСТВЕННЫЙ файл, который правишь руками ради нового выпуска
  static/<NN>/index.html     ← готовая страница выпуска — просто копия vypusk.html
  content/_index.md          ← заголовок и интро титульной, не трогать
  layouts/                   ← дизайн-шаблоны, не трогать
  .github/workflows/hugo.yml ← сборка, не трогать
```

Никакого корневого `site/index.html` больше нет — не искать, не создавать.

Новый выпуск собран в `vypuski/<ДАТА>-vypusk-<NN>/` — источник `vypusk.md`, готовая страница `vypusk.html`.

## 2. ГРАНИЦЫ

- Трогать разрешено: `site/data/vypuski.yaml`, `site/static/<NN>/`, и при необходимости строку `page_url:` в `vypuski/<ДАТА>-vypusk-<NN>/vypusk.md`.
- **Не трогать:** `site/layouts/`, `site/content/`, `site/hugo.yaml`, `site/.github/`, `materials.db`, `vypuski/build_vypusk.py`, `docs/`, другие `ZAHOD-*.md`, корневой `.git` репозитория `matemdigest-map`, ранее опубликованные выпуски в `site/static/`.
- Ничего из корня репозитория в публичный репозиторий не копировать.

## 3. ЗАДАЧА

1. Проверить, что в шапке `vypuski/<ДАТА>-vypusk-<NN>/vypusk.md` заполнено `page_url: https://d1-d57.github.io/digest/<NN>/`. Если пусто — вписать и пересобрать: `cd vypuski/<ДАТА>-vypusk-<NN> && python3 ../build_vypusk.py vypusk.md`. Генератор чистый stdlib, сети не требует; линтер должен быть зелёным.
2. Скопировать `vypuski/<ДАТА>-vypusk-<NN>/vypusk.html` в `site/static/<NN>/index.html` (папку создать).
3. Дописать выпуск **первой записью** (пять строк — `nomer`, `data`, `zagolovok`, `opisanie`, `ssylka`) в `site/data/vypuski.yaml`, по образцу уже лежащей там записи. `opisanie` — одна фраза того же регистра, что у соседних записей: сжать `teaser` из шапки `vypusk.md`, не копировать целиком.
4. Закоммитить и запушить из `site/`: сообщение `выпуск <NN>: <подзаголовок>`. Если `git push` откажет с `! [rejected] ... fetch first` — не форсить; `git fetch && git log origin/main` и разобраться, что изменилось в структуре `site/`, прежде чем продолжать (см. «Что выяснилось» ниже).
5. Дождаться сборки. Это GitHub Actions, не Pages-branch-build: опрашивать `gh api repos/d1-d57/digest/actions/runs --jq '.workflow_runs[0] | .status + " " + (.conclusion // "null")'` в цикле, пока не `completed success`, максимум 5 минут (обычно укладывается в минуту).
6. Curl-ом проверить 200 на титульной и на **каждом** опубликованном выпуске, не только новом:
   - `https://d1-d57.github.io/digest/`
   - `https://d1-d57.github.io/digest/1/`, `/2/`, … по числу выпусков
   На странице нового выпуска проверить наличие характерной строки из его текста.

## 3b. ЕСЛИ В ВЫПУСКЕ ЕСТЬ ФОРМУЛЫ

Страница подтягивает **KaTeX** с `cdn.jsdelivr.net` и рендерит `$…$` в строке, `$$…$$` — отдельным блоком.

Скриншот Browser pane для этой проверки может не сработать (наблюдался сплошной чёрный кадр независимо от прокрутки — похоже на баг капчура пейна в песочнице, не связан с сайтом). Надёжнее — прогнать в открытой странице JS (`javascript_tool` или консоль):

```js
document.querySelectorAll('.katex').length        // > 0 — формулы отрисованы
document.querySelectorAll('.katex-error').length  // 0 — ошибок парсинга нет
/\$[^\s$]/.test(document.body.innerText)          // false — сырых $…$ не осталось
```

Если `.katex` пусто и/или в тексте остались `$…$` — KaTeX не загрузился (обычно сеть/CDN). Не чинить, описать что видно и остановиться, выпуск оставить опубликованным.

## 4. ПРОВЕРКА ПЕРЕД ОТЧЁТОМ

- `git -C site ls-files` — `data/vypuski.yaml` и по одному `static/<NN>/index.html` на каждый выпуск, плюс неизменные `content/_index.md`, `layouts/*`, `hugo.yaml`, `.github/workflows/hugo.yml`. Корневого `index.html` быть не должно.
- Ранее опубликованные выпуски отвечают 200 по-прежнему.
- Корневой репозиторий изменён только в `vypuski/<ДАТА>-vypusk-<NN>/` и в этом файле.

## 5. ОТЧЁТ → секция `## ОТЧЁТ`

Адреса, коды ответов, вывод `git -C site ls-files`, результат проверки KaTeX (если была), что пошло не по плану, wall-clock.

---

## ПЛАН — (заполняет исполнитель)

## ВОПРОСЫ — (заполняет исполнитель)

## ОТЧЁТ — (заполняет исполнитель)

## Что выяснилось на первом прогоне (выпуск 1)

- **`page_url` не попадает в HTML выпуска** — генератор кладёт его только в `vypusk.teaser.txt` и `vypusk.telegram.txt`. Поэтому копировать страницу в `site/` можно сразу после сборки, второго коммита «дописать адрес» не нужно.
- **Pages собирается примерно за полминуты**, опрашивать чаще смысла нет.
- В окружении исполнителя опрос статуса в цикле спотыкался о постороннюю ошибку `sudo: a terminal is required`. На дело не влияет, обходится одиночным вызовом `gh api`.
- Учётка владельца: `d1-d57`, публичный репозиторий `digest`.

## 2 августа 2026 — сайт переехал на Hugo, этот шаблон устарел и подвёл на выпуске 3

Коммит `0031558` перевёл `site/` с ручного `index.html` на Hugo: список выпусков — теперь данные (`data/vypuski.yaml`), титульная — шаблон (`layouts/index.html` + `content/_index.md`), сборку и деплой делает GitHub Actions при пуше, источник Pages — workflow. Страницы самих выпусков (`static/<NN>/index.html`) не изменились — по-прежнему просто копия `vypusk.html`, только переехали из `<NN>/` в `static/<NN>/`.

Заход на выпуск 3 (9 августа) получил старый текст этого шаблона и честно пошёл по нему: отредактировал несуществующий `site/index.html`. Спасло то, что `git push` **отказал** (`! [rejected] ... fetch first`) — remote успел уйти вперёд. Если бы push прошёл (например, если бы `site/` уже был на Hugo локально, но заход всё равно правил не те файлы), список выпусков остался бы без новой записи, а правка мёртвого файла осталась бы незамеченной. **Отказ push — сигнал сверить структуру `site/` с реальностью, а не повод форсить.**

Комментарий в самом `data/vypuski.yaml` теперь и есть краткая инструкция: «Положил готовый выпуск в static/<номер>/index.html — допиши сюда пять строк.» Это и есть весь деплой контента; `site/index.html` для этого больше не существует.

`gh api repos/d1-d57/digest/pages/builds/latest`, которым пользовались раньше, для workflow-источника Pages **не годится** — это API для branch-based деплоя и молчит. Статус сборки теперь смотрят через `gh api repos/d1-d57/digest/actions/runs`.

Скриншот Browser pane для проверки KaTeX не сработал (сплошной чёрный кадр на любой прокрутке); заменён на прямую JS-проверку DOM — см. §3b выше.
